\begin{abstract}
This report documents the decision-tree and logistic-regression phases of the Tema 2 practical work in Explainable Artificial Intelligence. Across five stratified folds, the default logistic model achieves 0.788 +/- 0.000 accuracy but only 0.501 +/- 0.001 balanced accuracy, with 0.002 +/- 0.002 recall for the difficult-payment class. Hyperparameter tuning with balanced class weights raises its hold-out balanced accuracy to 0.680, at 0.713 accuracy. On the same validation split, the optimized tree obtains 0.609 balanced accuracy and 0.813 accuracy. The comparison illustrates the trade-off between overall accuracy and balanced detection of both classes.
\end{abstract}

\section{Introduction}

The task is a binary classification problem based on customer credit and repayment information. The training data contain the target variable \texttt{payment\_difficulty\_next\_month}; the test data contain the same predictors without that target. The objective is both predictive and explanatory: the model should produce test predictions while allowing its behavior to be inspected.

The decision-tree and logistic-regression implementations are provided in the Phase I and Phase II notebooks under \texttt{code/}. Both use a reproducible preprocessing pipeline, hold-out validation, and model-specific prediction exports, while their model families and explanation methods remain distinct. The default models favor the majority class; balanced-class hyperparameter tuning improves balanced accuracy, though the logistic model does so at the cost of lower overall accuracy.

The tuned decision tree predicts class 1 for only 4.1\% of test observations. Balanced accuracy and class-specific recall are therefore essential evidence rather than presenting accuracy in isolation. The logistic model's higher hold-out balanced accuracy is promising, but it should be considered alongside its lower accuracy and its class-specific errors.

\section{Data and preprocessing}

The notebook defines the feature roles explicitly rather than selecting columns implicitly. The identifier and target are excluded from the predictor matrix, while demographic, credit-limit, billing, payment, and repayment variables are used as predictors. Sex is retained as an audit attribute as well as a predictor, which makes later fairness-oriented analysis possible.

The categorical variables are sex, education, marital status, and repayment assistance plan. They are transformed with one-hot encoding using \texttt{handle\_unknown=\allowbreak"ignore"}, so categories that appear only in the test split do not cause prediction failures. Numerical variables are concatenated with the encoded categorical variables without additional scaling.

The labeled training data are split into training and validation partitions with a 70/30 ratio, a fixed random seed of 411, and stratification by the target. The unlabeled test data remain untouched until the final prediction stage. This procedure gives a reproducible validation estimate while preserving the test set for submission.

\section{Method}

The implementation uses pandas for tabular data loading and manipulation, scikit-learn for the stratified split, one-hot encoding, logistic-regression parameter search, and evaluation metrics, and InterpretML for the class histogram, classification tree, logistic regression, and model explanations. Matplotlib is used for the feature-importance and predicted-class proportion plots. Shared data preparation and prediction-export functions are defined in \texttt{code/common.py}; dependencies are listed in \texttt{code/requirements.txt}.

Only the labeled training data are split. Seventy percent is used for fitting and thirty percent for validation, with stratification preserving the class proportions and \texttt{random\_state=411} making the result reproducible. The separate test file is never used to fit the encoder or model: its categorical values are transformed after the encoder has been fitted on the training partition, with unknown categories ignored.

The notebooks use five-fold stratified cross-validation to characterize the default models and select hyperparameters using balanced accuracy. For the tree, the selected depth is 5 and the minimum leaf size is 50, with a best search score of 0.690. For logistic regression, the selected settings are $C=100$ and balanced class weights, with a best search score of 0.671. Each final model is evaluated separately on the same 30\% hold-out partition. A grid-search score is a parameter-selection result, not an independent estimate of the final refit. The separate test file is not used in model selection or validation. The Explainable Boosting Machine remains to be added for the complete three-family comparison.

\section{Models}

The classifier is \texttt{ClassificationTree} from the \texttt{interpret} package. A decision tree is suitable for this phase because its decision structure can be inspected directly and because the package exposes global explanations of the fitted model \citep{nori2019interpretml}. We used \texttt{GridSearchCV} to optimize hyperparameters, selecting a \texttt{max\_depth} of 5 and \texttt{min\_samples\_leaf} of 50 based on balanced accuracy. The notebook also displays a class histogram for the training data, a confusion matrix, and a ROC curve with AUC metric.

The tree is transparent in principle: each prediction can be traced through a sequence of feature conditions, and the global explanation exposes the learned structure. Logistic regression offers a different form of transparency: its prediction is an additive function of the encoded features, and the coefficient magnitudes identify which terms most affect the fitted score. Neither representation should be interpreted causally, and the different explanation formats are not directly interchangeable.

The optimized tree's global explanation is generated with \texttt{tree.explain\_global}. Its split-based feature-importance ranking places repayment status and the payment-to-bill ratio among the most influential features; this ranking describes the fitted tree and should not be read as a causal effect.

Figure~\ref{fig:tree-overview} shows the first three levels of the optimized tree. The full depth-five tree is available in the notebook; limiting the report view keeps its main decision structure readable without hiding that lower-level branches exist.

\section{Test predictions}

Once validation is complete, each fitted model predicts the unlabeled test set. The notebooks preserve the original test predictors, append \texttt{predicted\_class}, and save separate files: \texttt{data/decision\_tree\_test\_predictions.csv} and \texttt{data/logistic\_regression\_test\_predictions.csv}. \section{Limitations and future work}

The current comparison includes a tree and logistic regression, but its grid-search scores are selection results and should not be treated as independent estimates. Future work should add the Explainable Boosting Machine, compare all three families under the same protocol, and assess threshold choices and class-specific error costs when false negatives and false positives are unequal. The tuned logistic results should also be supplemented with class-specific hold-out metrics when reporting the final model comparison.

The notebook already preserves sex as an audit attribute, but it does not yet calculate group-wise performance or fairness measures. A subsequent phase should compare error rates across relevant groups, inspect feature-importance stability, and use local explanations for the same representative instances across all three model families, including at least one instance from each class. Any such analysis should be performed without using the test labels.

\section{Discussion}

The tree is attractive because its rules can be communicated directly, while the logistic model provides an additive explanation through its coefficients. On the shared validation split, logistic regression achieves higher balanced accuracy than the tree after class-weighted tuning, but at lower accuracy. This reinforces the need to choose a model using the class-specific costs of errors rather than accuracy alone. Both tuned models improve on their majority-class-biased defaults, although the logistic model's default class-1 recall is almost zero.

Interpretability also has a cost. A fully expanded tree can become a long and repetitive list of rules, making individual paths technically transparent but difficult to understand. Limiting the depth to 5 not only improved the balanced accuracy but also restricted the tree size, making the global and local explanations much more understandable. The same trade-off should be assessed for logistic regression coefficients and additive feature-effect plots rather than assuming that one explanation format is universally superior.

\section{Conclusion}

The decision-tree and logistic-regression phases establish a reproducible pipeline from raw credit and repayment data to interpretable models and separate test prediction files. On the hold-out split, the tuned tree reaches 0.813 accuracy and 0.609 balanced accuracy, while tuned logistic regression reaches 0.713 accuracy and 0.680 balanced accuracy. The tree is more accurate overall; the logistic model is more balanced across classes. Adding the Explainable Boosting Machine and considering the cost of missed payment-difficulty cases are necessary before selecting a final model.
